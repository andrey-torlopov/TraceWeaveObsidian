# Хранение, отчёты и перенос

Версия 0.1.3 сохраняет введённое в 0.1.2 расположение технических данных в скрытой `.twdata/`: JSON, history/journal/drafts/reports — `projects/<UUID>/`, настройки — `settings.json`, staging/экспорты/восстановление — `imports/`, `exports/`, `recovery/`. Новые обычные заметки создаются в видимой `Исследования/Заметки/`, управляемые копии оригиналов — в `Исследования/Вложения/`. Подключённые существующие заметки остаются в своих обычных папках vault.

Домен имеет формат `traceweave.obsidian-project/1.0`. Одна подтверждённая версия проекта — `.twdata/projects/<UUID>/state.json`. Связи и пути заметок живут только там. У Markdown нет служебного frontmatter или соседних sidecar. Нативные файлы заметок остаются источником текущего текста. Hash заметки — baseline привязки и обнаружения изменений, а не вторая копия текста. Схема читает исторические report paths с `_TraceWeave/`, `TWData/` и `.twdata/`; текущие записи создаются в `.twdata/`.

Имена файлов материалов недоверенные: путь строится по сгенерированным UUID, от исходного имени используется только безопасный ASCII-суффикс. Оригинальное имя сохраняется в Asset. Оригинал неизменяем; Blob несёт SHA-256 и размер, Asset — описание, Attachment — конкретную привязку к узлу. Проверка недоступного или изменённого файла не удаляет каталог. Symlink внутри управляемых путей запрещён. Не подменяйте `.twdata`, папки заметок или оригиналов внешними symlink.

Копирование и hashing выполняются потоками по 64 KiB, размер оригинала до 512 MiB. Отмена не регистрирует материал. MIME расширения недостаточно для запуска preview: сигнатура проверяется отдельно; HTML/SVG/архивы и неизвестные байты остаются generic. Плагин не распаковывает пользовательские ZIP-материалы автоматически.

Отчёт захватывает явный набор активных узлов, отношения между ними, привязанные материалы и их собственные копии. Упоминания внешних источников не расширяют состав скрытно. В скрытой папке снимка находятся JSON с текстами, читаемый Markdown, hashes и оригиналы. Отчёт открывается read-only представлением плагина. Лимит предпросмотра — 16 MiB; более крупный допустимый отчёт сохраняется целиком, а UI объясняет ограничение и предлагает **«Показать файл снимка»** в файловом менеджере. PDF и другие захваченные файлы также можно показать в файловом менеджере. Эти исторические копии текста намеренны и не служат параллельным редактором текущих заметок. Перенос расположения меняет путь реестра, но не байты snapshot.json, report.md, integrity.json и захваченных originals. Видимые исходные PDF остаются доступны штатному viewer Obsidian.

Backup 1.0 содержит project.json, manifest.json и пронумерованные payloads. Manifest связывает каждую запись с исходным путём, ролью, byteSize и SHA-256. Reader принимает backup из всех трёх исторических metadata roots. Экспорт включает принятый project state, все заметки, оригиналы и файлы snapshots. История команд, несохранённые буферы других редакторов и UI cache в этот формат не входят. Полную побайтовую копию vault делайте при закрытом Obsidian **включая скрытую `.twdata/`**. UUID при импорте переназначаются; изменение идентичности импортированной копии не является правкой исходного исторического снимка.

Импорт проверяет manifest, JSON с запретом повторных ключей, схему и ссылки, размер, SHA-256 и CRC ZIP до публикации проекта. Пределы: 50 000 записей, 10 GiB ZIP, 20 GiB распакованного содержимого, expansion ratio не более 1000; отдельные JSON имеют дополнительные лимиты. Пустые/абсолютные/не-NFC пути, `..`, `\\`, symlink, case collision, шифрованные записи и неучтённые payloads отклоняются. Безопасный компонент `.twdata` не означает traversal и не запрещён в ZIP. Распаковка пишет только сгенерированные имена в `.twdata/imports/`; пользовательский ZIP-path не является путём записи.

**Известное ограничение импорта ZIP:** обычные wikilinks и относительные Markdown-ссылки на файлы/изображения переназначаются не полностью. Они могут сохранить старый адрес, перестать работать или вести к исходным файлам. Это отдельный механизм от корректного переназначения графовых отношений и зарегистрированных вложений; проверяйте ссылки после импорта. Полная файловая копия vault сохраняет исходное расположение.

Новый проект получает новые UUID и собственные видимые папки в `Исследования/Заметки` и `Исследования/Вложения`; отчёты и retained sources попадают в `.twdata/projects/<new UUID>/`. Публикация state выполняется последней координатором repository, после успешной проверки и копирования всех файлов. У исходного проекта ничего не изменяется. Typed Markdown destinations `node:`, `asset:`, `relation:` переназначаются; UUID в произвольном тексте, origin и extensions не заменяются слепым поиском.

TraceWeave archive 2.0 валидируется по локальной закреплённой JSON Schema и её hash из archive index, без загрузки схем из сети. Серверный writer создаёт настоящий manifest/project/presentation/blobs archive 2.0 и проверяет их той же схемой; unsupported MIME передаётся generic без изменения байтов. Plugin backup 1.0 остаётся отдельным форматом и не передаётся серверному importer. Reader archive 1.0 сначала проверяет один из двух закреплённых исторических schema profiles, затем добавляет только определённые defaults: двусторонность false и стандартную камеру. Никакие неизвестные поля не отбрасываются. Старый Obsidian export распознаётся по metadata/snapshot.json + metadata/files.json. Текущий rendered Markdown документов принимается целиком, без regex-вырезания сгенерированных секций и без перезаписи старым body. Топология и семантика проверяются через общий доменный контракт. Весь исходный ZIP сохраняется потоково в центральной папке sources/ с SHA-256 и включается в plugin backup; это сохраняет изменения Relations/README и исходный исторический snapshot. Import warnings описывают активный состав старого формата, отсутствие корзины/отчётов, сохранение rendered Markdown и явные defaults недостающей раскладки. Backup с retained source может достичь лимита ZIP раньше из-за намеренного сохранения исходника; в таком случае нужен файловый backup всего vault, содержимое не отбрасывается молча.


## Прямое подключение обычной заметки

`adoptNote` регистрирует исходный vault-relative path и SHA-256. Файлового эффекта записи/копирования заметки нет: frontmatter, разметка, CRLF, wikilinks и относительные ссылки сохраняются. Текст читается из этого же файла; штатные modify/rename/delete события обновляют только централизованные bindings и baseline. При повторной привязке пользователь явно выбирает файл; ID узла и отношения сохраняются.

Путь вне папки исследований означает обычную заметку **внутри того же vault**, а не произвольный абсолютный путь диска. Absolute path, traversal за пределы vault, symlink и технические папки не допускаются. В списке подключения доступны обычные видимые Markdown-файлы всего vault и `Исследования/Заметки`; `.twdata` и старые технические папки не используются как заметки. Нативный Vault API работает только с видимыми файлами, скрытые читаются адаптером/файловым слоем плагина. [Официальная документация Vault API](https://docs.obsidian.md/Plugins/Vault).

Для ссылок/изображений учитывается sourcePath заметки. Root host использует публичное разрешение ссылок Obsidian, затем проверяет путь, принадлежность vault, symlink, размер и media signature. Рендерятся только безопасные локальные media; удалённые изображения и raw HTML не исполняются. Inline-файл не копируется в immutable library и не становится Asset без явной команды. Поэтому произвольные linked files не добавляются скрытно в отчёты или plugin backup; целый обычный vault с такими ресурсами копируется как файловый backup.

## Миграция 0.1.0/0.1.1 → 0.1.2

Для прямого обновления 0.1.0 сначала выполняется прежний проверяемый переход `_TraceWeave` → `TWData`. Затем профиль 0.1.1 переводится в скрытые технические данные и видимое содержимое. Текущий marker — `.twdata/layout-migration.json`; прежний `TWData/migration.json` сохраняется без изменения байтов как `.twdata/migration.json`. Миграция получает writer старого хранилища, восстанавливает журналы, строит план с hashes и проверяет отсутствие конфликтующих целевых файлов. Новые состояния/история/журналы подготавливаются с обновлёнными путями. Оригиналы материалов и immutable report files не переписываются; их перенос проверяется по байтам. Подтверждённые UUID, ревизии, receipts и предметные отношения не меняются.

`TWData/notes` и `TWData/resources` переезжают в `Исследования/Заметки` и `Исследования/Вложения`, технические данные — в `.twdata`. Для нестандартных старых roots перемещаются только распознанные управляемые заметки/зарегистрированные blobs; одно совпадение prefix с общей пользовательской папкой не делает обычную подключённую заметку управляемой. Остальные adopted paths остаются прежними.

Перенос заметки сохраняет смысл её относительных ссылок: Markdown destinations, reference definitions и wikilinks корректируются по карте переноса с учётом старого и нового sourcePath. Для обычных неперемещаемых заметок изменяются только адреса, указывающие на перемещённые управляемые файлы. Исходные Markdown-файлы перед изменением сохраняются в `.twdata/recovery/`; hashes привязок и history обновляются согласованно. Разбор использует позиции Markdown-токенов: frontmatter, fenced/indented/inline code, raw HTML и обычный текст защищены от замены. Подписи, query и fragment сохраняются. Обычная заметка, не содержащая ссылок на перенесённые файлы, остаётся байт-в-байт прежней.

Поиск таких обратных ссылок ограничен обычными Markdown-файлами вне скрытых папок: до 50 000 файлов, до 64 MiB суммарного текста и до 5 MiB на заметку. Данные сверх ограничений не пропускаются молча: миграция останавливается с диагностикой. Это управляемая правка адресов при обновлении расположения, а не массовое форматирование заметок. Исторические отчёты и захваченный в них Markdown остаются неизменными.

Фазы `prepared`, `files`, `published`, `complete` фиксируются атомарно. Незавершённый перенос возобновляется после проверки предыдущих шагов. Исходные JSON второго перехода сохраняются в `.twdata/recovery/layout-0.1.1/<migration UUID>/TWData/`; recovery первого перехода также переносится под `.twdata/recovery/`. Принятые истории и пути заметок обновляются согласованно; исторические snapshot bytes остаются неизменны. Разрешение старых путей в плагине учитывает цепочку обоих переходов.

Перед обновлением остановите запись с других устройств/процессов и сделайте файловую копию vault. При ошибке не удаляйте marker или отдельные старые/новые папки, не объединяйте два существующих `projects` дерева вручную. Диагностика указывает конкретный конфликт; восстановление опирается на целый backup, marker и retained original JSON. Произвольный sync или повторное появление старого `_TraceWeave` после complete не считается новым достоверным состоянием.

Откат к 0.1.0 или 0.1.1 требует восстановления полной файловой копии vault до миграции, включая скрытые файлы. Формат домена остаётся 1.0, но старый плагин не понимает новое расположение; по одному номеру formatVersion совместимость отката не определяется. Recovery не заменяет полный backup для отката.

## Синхронизация и скрытые файлы

**Obsidian Sync не синхронизирует `.twdata`.** Файлы и папки, начинающиеся с точки, всегда исключены, кроме конфигурационной папки `.obsidian`. Настройка Sync all other types это исключение не снимает. Поэтому передача видимых заметок через Obsidian Sync не передаёт граф, отношения и историю TraceWeave. [Официальные правила Sync](https://help.obsidian.md/sync/settings).

Для переноса подтверждённого проекта используйте plugin backup; для резервной копии и отката всего состояния — файловую копию закрытого vault с явно включёнными скрытыми папками. Проверяйте, что `.twdata/projects/.../state.json` есть в копии. Иные файловые sync-сервисы требуют отдельной проверки скрытых файлов и не разрешают конкурентную запись с двух устройств.
