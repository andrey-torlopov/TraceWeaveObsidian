# Данные, сеть и границы защиты

*[English](../en/data-and-security.md)*

## Где находятся данные

Все данные исследования хранятся в выбранном vault. Подключённые существующие заметки остаются в обычных папках. По умолчанию плагин создаёт:

```text
Vault/
  обычные заметки и папки
  TWData/                          настраиваемая видимая папка данных
    projects/<папка исследования>/  оригиналы по типам файлов
    exports/<папка исследования>/   отчёты, ZIP и снимки
  .twdata/                         технические данные, не редактор заметок
    projects/                      JSON проектов, история, журналы, черновики
    settings.json
    imports/
    recovery/
```

Заметки существующих узлов остаются в своих папках. Новые используют настройку папки новых заметок Obsidian; подключение существующей не создаёт копию. **Настройки → TraceWeave → Папка данных** управляет только видимыми материалами и экспортом. Имена папок проектов сохраняются после переименования исследования; при совпадении добавляется номер.

`.twdata/` — скрытая служебная папка, а не временный кэш. В ней лежат идентификаторы, отношения, атрибуты, привязки файлов, координаты, история, настройки, технический staging и записи восстановления. В заметки не добавляются служебные YAML-поля; рядом не создаются JSON-sidecar. Актуальный текст читается из привязанного файла vault. Исторические журналы и recovery могут содержать прошлые тексты; старые неизменяемые снимки и исходные ZIP сохраняются там, где их создали прежние версии. Это сохранённая история, а не вторая текущая заметка. Новые снимки и сохраняемые источники импорта размещаются в видимой структуре.

При обновлении до 0.2.0 доступные зарегистрированные оригиналы копируются в видимые папки проектов с сохранением байтов и хешей. Прежние файлы остаются для существующих ссылок из заметок. Отсутствующие или изменённые оригиналы сохраняют прежние привязки для диагностики. Заметки узлов не перемещаются. Смена папки данных также копирует оригиналы и обновляет привязки; готовые отчёты и исторические снимки остаются на прежних местах. При прерывании процесса журнал переназначения сохраняется до завершения восстановления.

Не удаляйте `.twdata/` и не подменяйте управляемые пути symlink. Удаление плагина не удаляет файлы исследования. **Для возврата к 0.1.6 после обновления нужна полная копия vault до обновления, включая скрытые метаданные; одной установки прежнего bundle недостаточно.** Технические детали и миграция старого расположения — в [протоколе хранения](../storage.md).

## Что выходит в сеть

TraceWeave не подключает телеметрию, аналитику, LLM, автоматический сбор внешних данных и фоновые сетевые запросы. Для локальной работы не нужны аккаунт TraceWeave и backend. Удалённые изображения из Markdown автоматически не загружаются; raw HTML в preview плагина не исполняется.

Открытие внешнего URL — явное действие пользователя через приложение. Установка и обновление плагина средствами Obsidian/BRAT используют их сетевые соединения. Другие плагины Obsidian, средства резервного копирования ОС и выбранные сервисы синхронизации имеют собственное поведение.

При импорте TraceWeave читает только выбранные вами файлы или ZIP, в том числе вне vault, и копирует необходимые данные внутрь. Постоянная внешняя папка не подключается. Для редактируемой заметки сначала поместите её и относительные ресурсы в сам vault.

Desktop-плагин использует файловые API Node.js для скрытых метаданных, атомарных журналов, контрольных сумм и потоковых архивов. Выбор заметки получает список Markdown-путей через публичный Vault API, не отправляя содержимое наружу. Конфигурационные файлы исключаются по фактической папке настроек vault, включая пользовательское видимое расположение. Поэтому проверка может показывать информационные сообщения о файловом доступе и перечислении заметок. Валидаторы схем компилируются при сборке; в установленном bundle нет runtime-компилятора схем, а React renderer запрещает script-элементы и предзагрузку исполняемых ресурсов.

## Доступ и целостность

TraceWeave не шифрует данные на диске. Имеющий файловый доступ к vault может прочитать заметки, оригиналы, экспорт и скрытые метаданные. При необходимости используйте права доступа и шифрование ОС. Не добавляйте личные vault и ZIP с исследованиями в публичный репозиторий исходников.

Хеши выявляют изменения и проверяют перенос; они не подтверждают автора и достоверность источника. За оценки и выводы отвечает автор исследования. Просмотр изображения, аудио или видео требует допустимых байтов и поддержанного кодека; произвольные файлы остаются данными без исполнения содержимого.

Используйте одного активного писателя для vault. Конкурентная запись с нескольких устройств или процессов не поддерживается; файловая синхронизация не обеспечивает общую транзакцию.

## Obsidian Sync не переносит граф

**Obsidian Sync исключает `.twdata/`.** Папки с точкой не синхронизируются, кроме конфигурационной папки Obsidian. Включение дополнительных типов файлов это исключение не снимает. Видимые заметки могут появиться на другом устройстве без отношений и истории TraceWeave. См. [правила Obsidian Sync](https://help.obsidian.md/sync/settings).

Переносите исследование через backup плагина либо копируйте весь закрытый vault со скрытыми файлами. Для стороннего sync отдельно проверьте перенос скрытых данных и сохраняйте одного писателя; безопасная одновременная запись не подразумевается.
